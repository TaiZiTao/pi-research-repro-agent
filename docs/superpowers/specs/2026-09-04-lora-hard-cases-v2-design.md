# FP16 LoRA 易混淆动作改进设计

## 背景

Qwen3-0.6B 的首轮冻结盲测包含 100 条样本，其中工具调用与无需工具各 50 条。FP16 LoRA 相比 Base 将动作准确率从 54% 提升到 79%，Tool-needed F1 从 30.51% 提升到 94.74%。29 条动作判断正确的工具样本，其参数也全部匹配，因此当前 58% 的参数匹配率主要由动作选择错误造成，而不是独立的参数填写问题。

错误集中在四类状态混淆：`plan` 被判为仓库搜索、`execute` 被判为配置命令、`report` 被判为直接回答、`search_evidence` 被判为最终作答。现有训练生成器虽覆盖这些动作，但措辞和状态组合较固定。

## 方案比较

1. **状态驱动的难例增强（采用）**：针对四类混淆补充不同措辞、不同前置状态的单步决策轨迹。改动小，能直接检验 0.6B 模型是否学会状态转换。
2. **增加 epoch 或重复现有数据**：实现最快，但会加强模板记忆，无法解决新表达泛化，放弃。
3. **更换更大模型**：上限更高，但增加显存和推理成本，也削弱轻量 LoRA 实验的简历价值，暂不采用。

## 数据设计

- 新增 80 条训练轨迹，每个薄弱动作 20 条：`research_plan_reproduction`、`research_reproduction_execute`、`research_reproduction_report`、`research_search_evidence`。
- 每条样本显式包含决定动作所需的任务状态，例如“仓库核验已结束但计划未创建”“命令已配置且步骤仍为 pending”“验收已通过但报告未生成”“当前论文已导入但证据尚未检索”。
- 不复制旧盲测提示词，不继续提高 `__answer__` 的采样权重；训练仍使用 1.5 倍 answer multiplier。
- `search_papers.limit` 继续覆盖 2/3/4/5。

## 评测隔离

- 原 100 条盲测在查看错误后改称开发诊断集，不再作为最终成绩。
- 新建开发验证集 v2，用于决定本轮模型是否入选。
- 新建最终冻结集 v2，保持工具/无需工具 50/50；在模型根据开发集确定后，只运行一次 Base 和一次入选 LoRA。
- 分割脚本继续按规范化后的用户提示去重，并在 manifest 中记录最终集哈希与排除记录。
- 最终集运行后不再根据其错误修改本轮模型；若继续迭代，必须另建 v3 最终集。

## 训练与成功标准

- 模型：Qwen3-0.6B。
- 方法：FP16 LoRA，不使用 4-bit QLoRA。
- 单轮训练：1 epoch，保持现有 LoRA 配置；不做多组超参数搜索。
- 开发集入选门槛：动作准确率不低于 85%，Over-tool Rate 低于 10%，JSON 有效率不低于 98%。
- 最终结果如实报告，不以最终冻结集是否达到目标决定是否重训。

## 最小验证

- 测试新增训练轨迹数量、四类动作分布和状态字段覆盖。
- 测试训练集与开发/最终集无规范化提示词重合。
- 运行现有数据校验和少量评测单元测试。
- 保存训练指标、开发结果、最终 Base/LoRA 结果，但不提交模型权重。
