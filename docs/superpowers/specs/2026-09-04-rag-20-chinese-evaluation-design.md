# Coding Agent 单论文 RAG：20 条中文检索评测设计

## 目标

使用 `E:\paper\2026` 中的英文超分辨率论文，对 Coding Agent 当前单论文 RAG 做可复现评测。评测问题全部采用自然中文表达，比较 BM25、Dense 与 Hybrid 三条检索路径，最终只报告脚本真实输出。

## 语料选择

- 从目录中的 8 篇论文固定选择 5 篇，兼顾 Transformer、卷积、空间/频域建模等不同技术路线。
- 每篇论文设计 4 条问题，共 20 条；检索范围限定在问题对应的单篇论文内，与产品的单论文复现场景一致。
- PDF 使用当前运行时相同的 PyMuPDF 分页、切块和索引管线，不为评测单独修改 Chunk。

## 问题设计

每篇论文分别覆盖以下四类问题：

1. 模型整体结构或数据流。
2. 核心模块的作用或实现机制。
3. 训练数据、损失函数或关键超参数。
4. 消融实验、定量结果或效率结论。

问题全部使用中文自然改写，不直接复制论文原句，不堆砌模块全称、数据集名称和连续数值。问题可保留无法合理翻译的模型缩写，但不能仅依靠唯一缩写定位答案。

## Gold 标注

每条样本固定记录：

- `id`、`paper`、`category`、`query`；
- 一个或多个 `gold_chunk_ids`；
- 对应的 `gold_pages` 与 `evidence_text`；
- 简短的 `annotation_note`，说明证据为何能够回答问题。

以 Gold Chunk 命中为主要判定标准，页码只用于人工核验。答案跨相邻 Chunk 或表格被切分时允许多个 Gold Chunk，但必须在标注说明中写明原因。所有 Gold 均在正式运行检索前冻结。

## 对照方法与指标

使用相同语料、Chunk 和查询，分别评测：

1. BM25 稀疏检索；
2. Dense 向量检索；
3. 当前产品实际使用的 Dense+BM25 Hybrid 融合。

对三种方法统一统计 `Hit@1`、`Hit@3`、`Hit@5` 和 `MRR@5`，并保存每题返回的 Chunk、排名和得分。Top-5 未命中时该题 MRR 记 0。

## 防止指标虚高

- 不使用已有的关键词式 20 条问题，也不根据检索结果反向修改问题或 Gold。
- 不把“返回同一页上的任意 Chunk”视为命中，必须命中已标注的证据 Chunk。
- 不针对这 20 条测试问题调融合权重、Embedding 模型或切块参数。
- 保留全部失败案例，并在结果中说明中文查询检索英文论文的跨语言限制。
- 简历只采用本次冻结测试集的真实结果，同时注明“20 条中文人工标注问题”和单论文封闭集边界。

## 输出产物

- 20 条冻结中文标注数据；
- BM25、Dense、Hybrid 的逐题检索结果；
- 指标汇总及失败案例分析；
- 一条不超过两行、可直接放入简历的 RAG 描述。
